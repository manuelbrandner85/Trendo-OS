## 0.9.48

- **Neue Seite „🔗 Verbindungen“ (unter KI → Verbindungen und auf der Claude-Karte):** Hier verbindest du Trendo mit GitHub und Netlify und verwaltest die Erweiterungen deines Claude Code. Jede Person hat ihre eigene Anmeldung; geändert oder hochgeladen wird nur nach deinem Ja, alles steht im Protokoll
- **GitHub je Person:** Trendo nutzt die offizielle GitHub CLI (wird nach deiner Zustimmung pro Benutzer eingerichtet). „Mit GitHub anmelden“ öffnet GitHub im Browser – du gibst dort den angezeigten Code ein. Die Anmeldung liegt im eigenen Ordner der Person; Trendo liest und speichert dein Passwort nie
- **„⬆ GitHub“ im Claude-Chat jedes Studios:** Ein Klick, Name prüfen, „✓ Ja, hochladen“ – das Projekt wird als neues Repo hochgeladen, vorgegeben privat. Trendo-Hilfsdateien (.trendo), node_modules und Schlüsseldateien (.env, *.key) kommen nie mit
- **„🌐 Netlify“ im Webseiten-Studio:** Webseite mit einem Klick öffentlich ins Internet stellen. Beim ersten Mal legt Trendo eine neue Netlify-Seite an, danach wird nur der neue Stand hochgeladen; die Adresse steht im Chat. Den Netlify-Zugangsschlüssel legst du selbst bei Netlify an – er liegt geschützt im Tresor deiner Person
- **🔌 Erweiterungen von Claude Code im Blick:** Skills, Plugins (an/aus), Marktplätze und MCP-Server deines Claude Code auf einen Blick. Plugins installieren, ein- oder ausschalten und entfernen, Marktplätze und MCP-Server hinzufügen oder entfernen – über die offiziellen Befehle von Claude Code und erst nach deinem Ja. Geheime Werte (Schlüssel in MCP-Einstellungen, Adress-Zusätze) zeigt Trendo nie an
- **Sicher eingegeben:** Ungültige Plugin-Namen, Adressen ohne https:// oder Befehlszeichen werden abgelehnt, bevor irgendetwas ausgeführt wird
- **Korrektur:** Repo- und Seitennamen behalten Buchstaben mit Akzent (aus „Café“ wird „cafe“ statt „caf“), und ohne index.html legt Trendo bei Netlify gar nichts mehr an
