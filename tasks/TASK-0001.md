## Ziel
Die real vorhandene lokale Umgebung erfassen, damit ADR-0005 (Tech-Stack) und der P1-Plan auf Fakten beruhen. **Keine Installation, keine Konfigurationsänderung, keine Windows-/Treiber-/Firmware-Eingriffe.**

## Vorbereitung (durch Manuel)
1. Grok Build nach `docs/spec/grok/GROK_BUILD_LOCAL_SETUP.md` installiert und angemeldet? Falls nein → Ergebnis `BLOCKED: GROK_BUILD_NOT_INSTALLED` melden.
2. Repo klonen: `git clone https://github.com/manuelbrandner85/Trendo-OS C:\TRENDO\Trendo-OS`
3. Im Ordner `grok` starten, diese Datei als Auftrag übergeben. Berechtigungsmodus „Ask every time“.

## Schritte (alle nur lesend)
1. `git checkout -b p0/task-0001-inventur`
2. Grok Build: `grok --version`; falls verfügbar `grok inspect`, `grok mcp doctor`.
3. Git: `git --version`, `git status`, `git log -1 --oneline`, `git remote -v`.
4. Windows: Edition und Build (`[System.Environment]::OSVersion`, `Get-ComputerInfo -Property OsName,OsVersion,OsBuildNumber,OsArchitecture`).
5. Hardware: CPU, RAM gesamt, GPU(s) + Treiberversion, freier Speicher pro Laufwerk (`Get-CimInstance Win32_Processor`, `Win32_VideoController`, `Get-PSDrive -PSProvider FileSystem`).
6. Toolchains (nur Version, „NOT_FOUND“ falls fehlend): `node`, `npm`, `rustc`, `cargo`, `dotnet --list-sdks`, `python --version`, `pwsh --version`, Visual Studio Build Tools (`vswhere` falls vorhanden), WebView2 Runtime.
7. Programme (nur vorhanden ja/nein + Version): Chrome, Edge, Firefox, LibreOffice, Blender, Unreal Engine, Tesseract.
8. Sicherheit nur lesend: Secure Boot (`Confirm-SecureBootUEFI`, darf mit Fehler „nicht unterstützt/Zugriff verweigert“ enden), BitLocker-Status **nur falls ohne Admin lesbar**, sonst `NOT_CHECKED`.

## Testkriterien (Abnahme durch Grok Bot)
1. Jede Angabe im Bericht ist im Rohlog belegt; keine geschätzten oder erfundenen Werte.
2. Fehlende Tools stehen als `NOT_FOUND`, nicht ausgelassen oder geraten.
3. `git diff --stat main...p0/task-0001-inventur` zeigt nur Dateien unter `reports/`.
4. Keine Secrets, Tokens, E-Mail-Adressen, Seriennummern oder Pfade mit Benutzernamen (ggf. durch `<USER>` ersetzen) – das Repo ist öffentlich.
5. Kein Befehl mit Adminrechten, keine Installation, keine Änderung außerhalb des Repos (im Bericht ausdrücklich bestätigen).
6. GRK-001/GRK-002 nur dann `PASS`, wenn die Versions- bzw. git-status-Ausgabe im Log steht; sonst `FAIL`/`BLOCKED` mit Grund.
7. Bericht folgt dem Schema aus `AGENTS.md`: Scope/Änderung/Dateien/Tests/Logs/Pass-Fail-Blocked/Risiken/Freigabe/Nächster Schritt.
