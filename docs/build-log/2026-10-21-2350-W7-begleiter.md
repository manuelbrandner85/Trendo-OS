# W7 – Gegenstellen: Trendo-Begleiter (Linux/Pi) und Android über adb
- Neu: `src/Trendo.Companion` (`trendo-companion`), kopflos, für linux-arm64 (Pi) und linux-x64. Befehle: `pair` (6-stelliger Einmal-Code, 10 min, 5 Fehlversuche verbrennen ihn), `serve`, `status`, `forget`.
- HTTP nur aus Heimnetz/Loopback: `/health` offen; `/pair` gibt einmalig ein 256-bit-Token (gespeichert nur als SHA-256, Datei 0600); `/info` (Modell, RAM, Temperatur, Fähigkeiten), `/task/ocr` (Tesseract), `/unpair` nur mit Token. Feste Aufgabenliste, keine Befehle von außen.
- Installation nur für den Benutzer (systemd --user, kein root): `installer/companion/install.sh`, Pakete per `installer/companion/build.sh`.
- PC-Seite: Koppeln jetzt mit dem Code vom Gerät, Token im Schlüsselspeicher (nicht in geraete.json), „Details“ holt /info.
- Android: Modell/Version/Akku, Bildschirmfoto, neuestes Kamerafoto – nur mit Zustimmung, Audit mit SHA.
- Tests: echter HTTP-Server mit echter OCR auf der Box; UI koppelt die App mit echtem Begleiter. QEMU: arm64-Binärdatei unter qemu-aarch64 mit nachgebildetem Pi-5-Abbild – Kopplung, Info, Einmal-Code, Entkoppeln OK (reports/w7/qemu/).
- Ehrlich offen: keine echte Pi-/Android-Hardware; unter QEMU zeigen „ocr/video“ die Werkzeuge des Box-Rechners. Begleiter-Server-Tests laufen nur unter Linux. Module bleiben IN_PROGRESS, Issues offen.
